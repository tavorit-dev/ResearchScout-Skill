# 万象 · Wanxiang Skill — 初步设计方案

# 万象

WANXIANG

# 万象 · Skill

Wanxiang — Information Intelligence

建议定位：通用信息研究与知识发现

核心理念：观万象、辨真伪、探本源、成其知。

面向开放信息环境，帮助用户完成信息检索、资料调研、事实核验、趋势分析、知识整理与持续追踪。

## 一、产品定位

万象不是简单的搜索工具，也不只是网页爬虫，而是一个面向问题的信息研究与知识发现 Skill。

它的核心任务是：围绕一个研究目标，从多种信息来源中发现、筛选、验证、组织信息，最终形成有依据、可追溯、可持续更新的研究成果。

可以将它理解为一个具备研究能力的个人信息助手：

- 检索：找到信息。
- 调研：理解信息。
- 核验：判断信息是否可信。
- 分析：提取观点、规律与趋势。
- 沉淀：形成结构化知识。
- 追踪：持续发现新的变化。

### 与其他 Skill 的关系

结合现有 Skill 体系，可以形成清晰的能力分工：

| Skill          | 核心职责            | 主要产出       |
| -------------- | --------------- | ---------- |
| 万象 · Wanxiang  | 信息检索、调研、分析、知识发现 | 研究报告、资料库   |
| 格物 · Gewu      | 学习、理解、解读、拆解     | 学习笔记、原理图解  |
| 观象 · Guanxiang | 天气数据解读与辅助决策     | 天气判断、决策依据  |
| 天工 · Tiangong  | 写作辅助、内容组织与表达    | 文章、文档、图文内容 |

其中，万象负责获取和研究信息，格物负责深入理解知识，天工负责组织和表达内容。

## 二、核心能力设计

核心能力拆分为六个模块。

01\. 信息检索

基础能力

Information Retrieval

- 根据主题、问题、行业、关键词检索信息。
- 支持中英文、多来源、多轮检索。
- 支持网页、技术文档、论文、GitHub、新闻、报告等。
- 搜索结果去重、排序、分类与筛选。

02\. 专题调研

核心能力

Deep Research

- 根据研究目标拆解子问题。
- 设计检索策略和调研路径。
- 先研究近期动态，再补充历史背景。
- 从不同来源寻找支持、反对和补充证据。
- 根据研究结果动态调整下一轮调研方向。

03\. 信息核验

Fact Checking & Verification

- 追溯原始来源与发布时间。
- 区分事实、观点、推测和宣传内容。
- 对比多个来源的描述与结论。
- 识别信息冲突、过时信息和证据不足。
- 为关键结论标记可信程度。

04\. 信息分析

Information Analysis

- 提取核心观点和关键事实。
- 识别技术路线、行业趋势、竞品关系。
- 建立人物、组织、产品、技术之间的关联。
- 分析发展脉络、变化和潜在机会。
- 形成对比表、时间线和知识结构。

05\. 知识沉淀

Knowledge Curation

- 将资料按研究主题归档。
- 保存来源、摘要、标签、引用关系。
- 形成专题知识库和阶段性报告。
- 支持 JSONL、CSV、Markdown、SQLite 等格式。
- 支持本地 HTML 浏览和检索。

06\. 持续追踪

Continuous Intelligence

- 对指定主题进行增量检索。
- 发现新论文、新产品、新技术和行业动态。
- 对比当前信息与历史研究结果。
- 更新研究结论和知识缺口。
- 生成变化摘要和下一步研究建议。

## 三、核心工作模式

设计四种工作模式。它们是同一个 Skill 的不同任务入口，而不是四个独立 Skill。

| 模式   | 目标          | 典型场景                |
| ---- | ----------- | ------------------- |
| 快速检索 | 快速回答一个明确问题  | 某个项目是什么、某技术如何实现     |
| 专题调研 | 系统研究一个主题    | AI Agent 安全技术调研     |
| 对比分析 | 对多个对象进行横向比较 | Agent 框架、数据库、开源项目对比 |
| 持续追踪 | 关注一个主题的长期变化 | AI 技术趋势、行业动态、项目更新   |

### 1. 快速检索

适合问题边界明确、无需复杂研究的场景。

流程：

`问题理解 → 检索 → 筛选 → 信息核验 → 答案输出`

要求：

- 优先使用权威来源。
- 关键结论提供原始链接。
- 不需要强制建立完整研究档案。
- 控制检索深度和执行成本。

### 2. 专题调研

这是万象最重要的能力，也是与普通搜索工具区别最大的部分。

## 专题调研流程

1. 明确研究目标

   明确主题、研究问题、时间范围、关注方向与排除范围。
2. 研究任务拆解

   将复杂主题拆分为多个子问题，制定信息检索策略。
3. 信息源发现

   搜索候选来源，识别官方网站、论文库、技术社区等。
4. 来源合规检查

   检查网站访问规则、API 条款、robots.txt 和内容使用限制。
5. 分阶段信息采集

   优先收集近期资料，再围绕引用关系、关键缺口补充历史资料。
6. 分析与交叉验证

   去重、提炼证据、识别冲突，形成阶段性结论。
7. 反思与迭代

   根据本轮发现的问题，决定下一轮深入、扩展、核验或停止。
8. 成果归档

   输出研究报告、结构化数据、来源清单和本地 HTML 页面。

### 3. 对比分析

重点不是简单罗列功能，而是围绕统一维度收集证据。

例如对比三个 Agent 框架：

- 项目定位与设计理念
- 架构设计和核心机制
- 工具调用与多 Agent 能力
- 模型兼容性
- 部署和扩展能力
- 社区活跃度与维护状态
- 适用场景和局限性

最终输出结构化对比表、差异分析和选择建议。

### 4. 持续追踪

针对长期研究主题，建立可复用的研究任务。

例如：

- AI Agent 安全领域的新论文、新漏洞和新方案。
- Go 生态中值得关注的开源项目。
- 工业物联网与数字孪生技术进展。
- 特定开源项目的版本演进。

每次执行只关注新增信息，并与已有研究成果进行对比，避免重复调研。

## 四、迭代研究引擎：万象的核心差异化

建议保留之前设计的 ReAct 式研究循环，但将它提升为万象的核心引擎。

## Research Loop

行动 → 观察 → 思考 → 决策 → 再行动

Action · 行动

检索、访问、采集资料

Observation · 观察

分析新信息、提取证据

Reflection · 反思

更新摘要、识别知识缺口

Decision · 决策

深入、扩展、核验或停止

循环执行，直到达到研究目标或预算边界

每轮结束必须产生一份结构化研究状态，而不是只生成一段普通摘要。

建议包含：

```
iteration:
  round: 3
  new_findings: []
  high_weight_conclusions: []
  evidence:
    supporting: []
    contradicting: []
  knowledge_gaps: []
  new_leads: []
  next_actions:
    - type: deepen
      topic: Agent 工具调用权限隔离
      priority: 90
    - type: verify
      topic: 某项技术方案的实际效果
      priority: 85
  decision: CONTINUE
```

### 防止研究跑偏

这部分需要作为系统约束，而不是完全交给大模型自行判断。

- 核心研究范围：由用户明确指定。
- 关联研究范围：允许扩展，但必须解释与核心目标的关系。
- 排除范围：不允许自动扩展。
- 每轮新方向必须经过相关性评估。
- 设置最大迭代次数、最大采集数量和时间预算。
- 连续多轮没有有效新信息时自动停止。

同时，必须区分结论的重要性与结论的可信度：重要但证据不足的结论应进入核验队列，而不是直接成为研究事实。

## 五、信息源与合规机制

万象需要建立统一的信息源管理体系。

### 信息源分类

| 类型   | 典型来源             | 主要用途      |
| ---- | ---------------- | --------- |
| 官方来源 | 官方网站、官方博客、公告     | 权威事实      |
| 学术来源 | arXiv、论文、学术期刊    | 理论与技术研究   |
| 开源来源 | GitHub、GitLab    | 项目和代码分析   |
| 技术社区 | Hacker News、技术论坛 | 实践经验和社区反馈 |
| 媒体来源 | 行业媒体、新闻网站        | 动态与趋势     |
| 数据来源 | 开放数据集、政府统计       | 数据分析      |

### 合规机制

建议设置独立的 Compliance Gate：

1. 检查 robots.txt。
2. 检查网站服务条款。
3. 检查 API、RSS 的访问规则和频率限制。
4. 检查登录、授权和访问控制要求。
5. 确认允许保存和使用的内容范围。
6. 记录检查时间、规则依据和结果。

特别注意：robots.txt 并不等于授权许可，搜索引擎可以检索到的内容也不代表可以任意抓取和存储。遇到明确禁止、访问受限或规则无法确认的情况，应暂停采集或转人工审核。

建议默认优先使用官方 API、RSS 和公开授权数据源。

## 六、知识库与归档设计

万象的研究成果应该可以被后续研究复用，而不是每次从零开始。

建议采用：

- JSONL：原始结构化数据的主要存储格式。
- Markdown：研究摘要和报告。
- CSV：数据交换和表格查看。
- SQLite：后续支持跨专题检索、去重和全文搜索。
- HTML：静态可视化浏览。

### HTML 浏览器

建议第一版直接生成静态 HTML，不引入前后端服务。

主要页面：

1. 研究总览：专题数量、信息来源数量、文档数量、最近更新时间。
2. 专题详情：研究摘要、核心结论、证据、知识缺口、迭代历史。
3. 资料列表：支持关键词、来源、时间、类型和相关性筛选。
4. 资料详情：原始来源、摘要、关键内容、关联结论和原文链接。

## 七、技术实现建议

建议保持 Skill 本身轻量，将复杂能力拆分为脚本和可调用工具。

| 层级      | 主要职责               | 实现建议            |
| ------- | ------------------ | --------------- |
| Skill 层 | 理解用户意图、选择工作模式、编排流程 | SKILL.md        |
| 检索层     | 搜索、API、RSS、网页访问    | 搜索工具 + Python   |
| 分析层     | 摘要、分类、相关性、交叉验证     | LLM             |
| 研究引擎    | 任务拆解、迭代、停止判断       | Python + LLM    |
| 存储层     | 数据、证据、研究状态         | JSONL + SQLite  |
| 展示层     | 报告和知识浏览            | Markdown + HTML |

这里有一个重要设计原则：

不是所有环节都需要调用大模型。

- 搜索、下载、解析、去重：尽量使用确定性程序。
- 相关性判断、摘要、矛盾识别、研究反思：使用大模型。
- 合规规则、执行预算、权限控制：由程序强制执行。
- 关键事实：尽可能回到原始来源验证。

## 八、MVP 开发路线

不要一开始就开发成完整的研究平台。先做一个能够完整跑通研究闭环的 Skill。

1. 阶段一：基础检索

   第一优先级
   - 统一检索入口。
   - 多来源搜索。
   - 结果去重、分类和摘要。
   - 输出 Markdown、CSV、JSONL。
2. 阶段二：专题调研
   - 研究目标拆解。
   - 来源发现和合规检查。
   - 近期资料优先采集。
   - 历史资料补充。
   - 生成结构化研究报告。
3. 阶段三：迭代研究引擎
   - 研究状态持久化。
   - 每轮摘要与知识缺口提取。
   - 自动生成下一轮研究方向。
   - 研究范围和预算约束。
   - 支持中断恢复。
4. 阶段四：知识沉淀与展示
   - 多专题目录管理。
   - SQLite 检索。
   - 静态 HTML 浏览器。
   - 历史研究复用与增量更新。

## 九、第一版验收标准

可以使用一个实际研究任务来验证万象：

研究主题：AI Agent 安全技术发展现状与关键防护方案。

| 验收维度 | 验收标准                               |
| ---- | ---------------------------------- |
| 研究规划 | 能拆分至少 5 个合理子问题                     |
| 信息来源 | 能发现并管理多种类型的信息源                     |
| 合规控制 | 未通过检查的来源不会进入自动采集流程                 |
| 信息采集 | 能采集近期资料，并补充高价值历史资料                 |
| 信息质量 | 能去重、标注来源、提取证据                      |
| 迭代研究 | 至少完成 3 轮有效研究，并根据缺口调整方向             |
| 范围控制 | 不因关联话题而偏离核心研究目标                    |
| 成果输出 | 生成 Markdown 报告、CSV/JSONL 和 HTML 页面 |
| 可恢复性 | 中断后可以从上一次研究状态继续                    |

## 十、最终建议：明确万象的产品边界

万象的定位进一步明确为：

# 万象 · Wanxiang

## Information Research & Intelligence Skill

面向开放信息环境的信息检索、专题调研与知识发现工具。

通过多源信息检索、证据核验、迭代式研究和结构化知识沉淀，帮助用户从海量信息中发现有价值的内容，形成可信、可追溯、可持续更新的研究成果。

核心关键词

`Search` · `Research` · `Verify` · `Analyze` · `Discover` · `Archive`

补充三个设计决策：

1. 万象以研究任务为中心，而不是以网页为中心。 网页、论文、代码仓库只是信息来源，真正需要管理的是研究问题、证据和结论。
2. 迭代研究是核心竞争力。 普通检索解决一次性问题，万象要能够基于已有研究不断发现新问题、补充证据和完善结论。
3. 知识沉淀必须独立于单次对话。 研究状态、资料、结论和历史迭代都应该保存在本地，能够复用、更新和迁移。

后续规划： 万象不要过度局限于互联网爬虫。未来可以将本地文件、PDF 论文、代码仓库、项目文档以及用户提供的数据集也纳入统一的信息研究入口。这样它才真正具备“万象皆可探”的能力。
